# Rick IA V2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a secure, personalized Rick IA assistant to RICK_DEV OS 2.0 with floating text chat, private context, structured pending actions, proactive in-app insights, and push-to-talk voice.

**Architecture:** Keep React as the owner of normalized OS state and existing cloud sync. Add a Supabase Edge Function as the trusted AI boundary; it authenticates the admin, loads private profile/history, receives a minimized live-state snapshot, calls OpenAI, and returns either a message or a typed pending action. Mutations remain client-side through existing validation/state paths and execute only after explicit confirmation.

**Tech Stack:** React 19, Vite 6, Supabase JS 2.118.0, Supabase Postgres/RLS, Supabase Edge Functions (Deno), OpenAI Responses API, browser MediaRecorder/Audio APIs, Node test runner.

**Spec:** `docs/superpowers/specs/2026-11-02-rick-ai-v2.md`

## Global Constraints

- Public repository must contain no private Rick profile, private chat history, OpenAI secret, service-role key, or private OS snapshot.
- Rick IA may read all admin-visible modules but may never mutate data without explicit confirmation of the exact pending action.
- Guest mode must never expose private AI profile/history or permit AI mutations.
- AI provider calls happen only in the authenticated backend/Edge Function.
- Keep existing `normalizeData`, `validateRecord`, `setData`, and cloud-sync safeguards in the mutation path.
- Default language is Brazilian Portuguese and personality is close/direct/lightly teasing, with serious tone when needed.
- Voice must not clone or impersonate a real person; disclose AI-generated voice in UI.

## Review Focus

- Prompt injection inside user-entered OS content must not override system rules or authorize a mutation.
- Guest sessions must not receive Rick profile/history or actionable mutation proposals.
- A stale or tampered pending action must fail validation rather than modify state.
- Network/AI failures must leave the current OS state untouched and keep chat usable for retry.
- Repeated proactive insights must be throttled/deduplicated so the assistant does not become noisy.
